Scirocco Coding Rules

Introduction

This chapter provides detailed reference information for the Scirocco policy. Scirocco is a high-performance, high-capacity, full-language VHDL simulator. Scirocco's unique architecture combines cycle-based, performance-driven optimization techniques with the flexibility of event-driven simulation to deliver superior performance and capacity for complete system verification. Because Scirocco is a VHDL simulator, all of the rules in this policy are for VHDL only. They do not pertain to Verilog designs.

The rules included in the Scirocco policy check the coding style of your VHDL design and testbench files for compliance, speed, and accuracy in cycle-based simulation. The rules are organized into the rulesets shown in Table 2
Table 2: Scirocco Policy Rulesets
Ruleset
Description
"No Sim Ruleset" These rules check VHDL code for cycle-based mode simulation compliance.
"Wrong Sim Ruleset" These rules check VHDL code for segments that may create mismatch results between cycle-based mode simulation and event-based mode simulation.
"Slow Sim Ruleset" These rules check VHDL code for segments that slow cycle-based mode simulation performance.
"Chip Level Ruleset" These rules check an elaborated VHDL design hierarchy across multiple design entities.

SC_107

Message: Missing or redundant signals in the process sensitivity list.

Description In cycle-based mode, missing signals are automatically added to the sensitivity list and therefore can cause simulation mismatches when compared to event-based mode simulation. Redundant signals are ignored and thus are not a problem in cycle-based mode.
Policy SCIROCCO_CYCLE
Ruleset WRONG_SIM
Language VHDL
Type Block-level
Severity Warning

SC_108

Message: Level-triggered (latch) based logic is simulated as edge-triggered logic in cycle mode.

Description Level-triggered (latch) based logic is simulated as edge-triggered logic in cycle-based mode. To maintain correct latch functionality either:
    • Stick to pure multiphase non-overlapping clocks, or
    • Use the -latch_transparency option (note that this will degrade cycle-based simulation performance rapidly with each transparent latch).
This rule only checks at the architecture level. There is a similar rule in the Leda general coding guidelines policy that you can use to check the entire design.
Policy SCIROCCO_CYCLE
Ruleset WRONG_SIM
Language VHDL

Slow Sim Ruleset

The following rules are from the slow sim ruleset:

SC_200

Message: Null waveform not in an edge triggered section of code - extra cycle mode trigger.

Description Null waveforms that are not in an edge-triggered section of code generate extra cycle-based mode triggers. This degrades cycle-based mode simulation performance.
Policy SCIROCCO_CYCLE
Ruleset SLOW_SIM
Language VHDL
Type Block-level
Severity Warning

SC_201

Message: Variable assignment outside pure sequential region - extra cycle mode trigger.

Description When there is a variable assignment outside the pure sequential region, a sensitivity list of combinational logic is used as the cycle-based mode trigger. This degrades simulation performance in cycle-based mode.
Policy SCIROCCO_CYCLE
Ruleset SLOW_SIM
Language VHDL
Type Block-level
Severity Warning

SC_202

Message: Variable is read first on at least one flow of control - extra cycle mode trigger.

Description Variable is read first on at least one flow of control. This generates an extra trigger for simulation and degrades cycle-based mode simulation performance.
Policy SCIROCCO_CYCLE
Ruleset SLOW_SIM
Language VHDL
Type Block-level
Severity Warning

SC_204

Message: Use of both rising and falling edge triggered logic will yield extra cycle mode triggers which in turn will degrade simulation performance.

Description The use of both rising- and falling-edge triggered logic yields extra cycle-based mode triggers. This degrades simulation performance. Note that to check this rule on the entire design, you must specify a top design unit using the -top switch.
Policy SCIROCCO_CYCLE
Ruleset SLOW_SIM
Language VHDL
Type Chip-level
Severity Warning

SC_301

Message: In any cycle mode partitioned block, the clock should be an input to the block.

Description In any cycle-based mode partitioned block, the clock (a cycle-based mode trigger) should be an input to the top unit of the cycle-based mode partitioned block. This improves cycle-based mode simulation performance. Note that to check this rule on the entire design, you must specify a top design unit with the -top switch.
Policy SCIROCCO_CYCLE
