NTL_PAD05

Message: Controllable pull-up

Description This rule fires when Leda detects a pull-up pin that is not controllable because it is tied to a power signal. Make such pull-up pins pads controllable to avoid circuit faults. You can configure this rule using the rule_set_parameter Tcl command and the SUPPLY_LOW_LIST parameter to specify low-power signals that cannot be tied to the pull-up pin and the CTRL_PULL_UP_PIN parameter to specify the pull-up. The default power signal name for this rule is VSS and the default controllable pull-up pin name for this rule is PULLQ. For example:
leda> rule_set_parameter -rule NTL_PAD05 \
-parameter SUPPLY_LOW_LIST -value {LOW_P}
leda> rule_set_parameter -rule NTL_PAD05 \
-parameter CTRL_PULL_UP_PIN -value {DQ}
Note that the SUPPLY_LOW_LIST parameter that you can configure with this rule affects other rules in the verification run that also reference power signals, including NTL_PAD06 through NTL_PAD10.
Policy DESIGN
Ruleset PAD
Language VHDL/Verilog
Type Hardware
Severity Error

Example

This is an example of invalid Verilog code that illustrates the problem: 

module ntl_pad05_top;
...
supply1 VDD; //VDD is an signal in the supply_high_list (user provided)
supply0 VSS;  //VSS is an signal in the supply_low_list (user provide)

// signal named with '_pad' is an input/output of top-level
Design_core U0(Ctrl, Din, Dout);
...
//PAD cells -- PGI_ECS277Ex is an input cell, PULLQ is pull-up pin
PGI_ECS277Ex  U1( .PULL(VSS), .ENABQ(Enable), .PULLQ(VSS), 
                                   .PAD(Ctrl_pad), .OUTI(Ctrl));   
// NTL_PAD05 fires -- VSS is in supply_low_list (user provided). It is a 
// violation when a signal listed in supply_low_list is connected to
// the PULLQ pin of IOLIB cells

PGI_ECS277Ex  U2( .PULL(VSS), .ENABQ(Enable), .PULLQ(VDD),  
.PAD(Din_pad), .OUTI(Din)); 
// OK -- VDD is not in supply_low_list. You can connect VDD to U2.PULLQ 
...
endmodule
