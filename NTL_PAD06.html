NTL_PAD06

Message: Controllable pull-down

Description This rule fires when Leda detects a pull-down PAD pin that is not controllable. To avoid circuit faults, make such PADs controllable. You can configure this rule using the rule_set_parameter Tcl command and the SUPPLY_HIGH_LIST parameter to specify the high-power signals that cannot be tied to the pull-down pin and the CTRL_PULL_DOWN_PIN parameter to specify the pull-down pin. The default power signal name for this rule is VDD and the default controllable pull-down pin-name for this rule is PULL. For example:
leda> rule_set_parameter -rule NTL_PAD06 \
-parameter SUPPLY_HIGH_LIST -value {HIGH_P}
leda> rule_set_parameter -rule NTL_PAD06 \
-parameter CTRL_PULL_DOWN_PIN -value {DQ}

Policy DESIGN
Ruleset PAD
Language VHDL/Verilog
Type Hardware
Severity Error

Example

This is an example of invalid Verilog code that illustrates the problem: 

module ntl_pad06_top ;
...
supply1 VDD; //VDD is a signal in the supply_high_list(user provided)
supply0 VSS; //VSS is a signal in the supply_low_list (user provide)

// signal named with '_pad' is an input/output of Top-level
Design_core U0 (Ctrl, Din, Dout);
...
//PAD cells - PGI_ECS277Ex is an input cell, PULL is pull-down pin
PGI_ECS277Ex  U1 (.PULL(VDD), .ENABQ(Enable), .PULLQ(VDD), 
                           .PAD(Ctrl_pad), .OUTI(Ctrl));  
// NTL_PAD06 fires -- VDD is in the supply_high_list (user provided). It 
// is a violation when the signal listed in the supply_high_list is
// connected to the PULL pin of IOLIB cells

PGI_ECS277Ex  U2 ( .PULL(VSS), .ENABQ(Enable), .PULLQ(VDD), 
                           .PAD(Din_pad), .OUTI(Din));   
// OK -- VSS is not in supply_high_list. You can connect VSS to U2.PULL
...
endmodule
