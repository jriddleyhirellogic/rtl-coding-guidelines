Xilinx Coding Rules

Introduction

This chapter presents reference information for prepackaged rules in the Xilinx policy. These rules cover many aspects of coding for designs that are targeted for Field-Programmable Gate Array (FPGA) implementations. FPGA technology has advanced to the point where multi-million gate implementations running at 300 Mhz are now possible in deep sub-micron designs. With these increases in capacity and performance, FPGAs can now be used to implement reprogrammable systems on a chip (SOCs). To be feasible, large designs like this require the integration of reusable IP blocks. In that sense, the reuse challenge for FPGAs is similar to ASIC implementations. Therefore, many of the rules in this policy encourage good coding practices for design reuse. For more information, see the Xilinx Design Reuse Methodology for ASIC and FPGA Designers in the $LEDA_PATH/doc directory.

The rules in the Xilinx policy are grouped by type into the following rulesets according to different families of FPGA devices offered by Xilinx:

    • "Xilinx_Virtex2 Ruleset"
    • "Xilinx_Virtex2Pro Ruleset"
    • "Xilinx_Virtex_Spartan2 Ruleset"
    • "Xilinx_Virtex4 Ruleset"

XV2_1202

Message: Clock gating detected. Xilinx warns that you avoid gating the clock and instead use the CE input of the sequential elements for controlling the clock.

Description Do not use gated or multiplexed clocking schemes. Using gated clocks can cause undesirable effects such as false/double clocking, missed clocking, non-uniform clocking, and/or undesired clock skew in the design, resulting in unpredictable and unreliable behavior. It is strongly suggested that you use the register's clock enable instead of clock gating to control system operation. If clock gating is absolutely required, BUFGMUX and BUFGCE should be inferred or instantiated, and extra care should be taken to ensure that no glitches occur on the clock line that could affect design functionality. Care must also be taken to ensure that proper clock buffer insertion is achieved.Generally, it is best to not allow the synthesis tool to infer the clock buffers and instead instantiate the desired clock buffers. Additional care must also be taken when applying timing constraints and performing static timing analysis since proper timing analysis is generally more complicated in gated clock systems. Be sure to account for all clock skew both within the clock domain and between clock domains.
For more information on coding guidelines for clock enables, see Chapter 3 in the Xilinx Synthesis and Simulation Design Guide.
