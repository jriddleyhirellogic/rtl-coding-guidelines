DC Coding Rules

Introduction

This chapter provides detailed reference information for the Design Compiler (DC) policy for Leda. The Synopsys HDL compiler translates and optimizes an HDL design description into a gate-level netlist. This representation is then compiled with the Design Compiler tool to produce an optimized gate-level design in a given ASIC technology.

Many HDL language constructs, although useful for simulation and other stages in the design and verification process, are not relevant in synthesis. Because these constructs cannot be synthesized, the HDL compiler does not support them. A construct can be fully supported, ignored, or unsupported. Ignored and unsupported constructs are defined as follows:

    • Ignored means that the construct is allowed in the HDL source but is ignored by the HDL compiler.
    • Unsupported means that the construct is not allowed in the HDL source and the HDL compiler flags it as an error. If there errors are in an HDL description, the description is not translated (synthesized).

Appendix C in the VHDL Compiler Reference Manual lists all the VHDL language constructs for VHDL, and Appendix B in the Verilog Compiler Reference Manual provides a similar list for Verilog, with the level of support noted for each. The DC coding guidelines in this prepackaged policy result from this varied level of support for different HDL constructs in the Design Compiler tool. Note that the rules in this DC policy were extracted and classified from man pages in the DC 2000.11 version of Design Compiler. The VCS policy includes the rulesets shown in Table 2.

DCHDL_109

Message: This use of clock edge specification not supported.

Description This error occurs if you use more than one "if clock event" expression in a process or if you enter the 'event expression inside a subprogram or loop.
Policy DC
Ruleset RTL
Language VHDL
Type Block-level
Severity Error

Example

Subprograms are sequential statements that are used to perform repeated calculations, often in different parts of the architecture. Subprograms are different from processes in that subprograms cannot directly read or write signals from the rest of the architecture. The communication is only through the subprogram interface. Therefore, 'event is not allowed in subprograms.

For loop statements are used to have repeated hardware structures. Therefore, 'event would break the structure during the time of unrolling.

Process statements should be active to only one clock expression.

A limitation of this rule is that it cannot check if two clock'event of the same edges are made use of in a process, which is not usually the case.

Invalid VHDL Code: 

--VHDL CODE to CHECK : The use of unsupported clock-edge in a process
--This is a block level check
--Author : Praveen
--This code generates error at the place marked FAIL

entity test is
        port (
                clock, a : in bit; -- PASS
                z1, z2 : out bit); -- PASS
end test;

architecture a of test is
begin
        process (clock) -- FAIL
        begin
                if (clock'event and clock='1') then -- PASS
                        z1 <= a;                    -- PASS
                end if;
                if (clock'event and clock='0') then -- PASS
                        z2 <= a; -- PASS
                end if;
        end process;
end a;

Valid VHDL Code: 

--VHDL CODE to CHECK : The use of unsupported clock-edge in a process
--This is a block level check
--Author : Praveen
--This is good code

entity test1 is
        port (
                clock, a : in bit; -- PASS
                z3 : out bit); -- PASS
end test1;

architecture a of test1 is
begin
        process (clock) -- PASS
        begin
                if (clock'event and clock='1') then -- PASS
                        z3 <= not a; -- PASS
                end if;
        end process;
        process (clock) -- PASS
        begin
                if (clock'event and clock='0') then -- PASS
                        z3 <= a;
                end if;

end a;

DCHDL_175

Message: Clock variable is being used as data

Description Synthesis does not support the use of a value as both clock and data in the same process.
Policy DC
Ruleset RTL
Language VHDL/Verilog
Type Chip-level
Severity Error

Example

Synthesis does not support the use of a value as both clock and data in the same process. A limitation of the tool is that it will not recognize a clock used as data if the clock signal is used as data first and then the wait on clock'event is written. This is because when a clock signal drives the data pin of a cell, the ATPG tools cannot determine the captured value. Therefore, if you need to compute a value that is based on a clock signal (for example, to generated a gated clock), then you must perform the computation outside any process that is sensitive to the clock edge. Following are examples of valid and invalid VHDL code that illustrate this problem and how to fix it.

Invalid VHDL Code: 

--VHDL CODE TO CHECK THE RULE : Clock variable being used as data
--This is a CHIP-LEVEL check 
--Author : Praveen 
--This code generates the error at the place mentioned FAIL
library IEEE;
use IEEE.std_logic_1164.all;

entity ex175 is
generic (n : integer :=8); -- PASS
	port (
		A : in std_logic_vector (n-2 downto 0); -- PASS
		clock, D : in std_logic; -- PASS
                C : out std_logic; -- PASS
		B : out std_logic_vector (n-1 downto 0)); -- PASS
end ex175;

architecture rtl of ex175 is
begin
regh_proc: process (clock) -- PASS
begin
	if (clock'event and clock='1') then  -- PASS
		B <= clock & A; -- FAIL
	end if;
end process; -- PASS
wait_pro : process 
begin
	wait until clock'event and clock='1'; -- PASS
        C <= clock and D; -- FAIL
end process;
end rtl;

--This is a CHIP_LEVEL check
--Author : Praveen
--THis is a good code and will not generate any error

use IEEE.std_logic_1164.all;

entity reghgood is
generic (n : integer :=8);
	port (
		A : in std_logic_vector (n-1 downto 0); -- PASS
		clock : in std_logic; -- PASS
		en : in std_logic; -- PASS
		B : out std_logic_vector (n-1 downto 0)); -- PASS
end reghgood;

architecture rtl of reghgood is

begin

DCHDL_177

Message: Local variable is being read before its value is assigned. This may cause simulation not to match synthesis.

Description The VHDL compiler assumes that processes should run whenever doing so would change an output value. If a description is written so that the simulator might not execute a process even though doing so could change an output, the VHDL compiler issues a warning.
Policy DC
Ruleset RTL
Language VHDL
Type Block-level
Severity Warning

Example

The incomplete sensitivity list warning (see HDL-179) tells when a signal is read but it is not on the sensitivity list. DCHDL_270

Message: An unsupported expression is assigned to constant

Description Synopsys does not synthesize logic for HDL descriptions in constant declarations. All constants must be computable during HDL compilation. Therefore, the computation in constant declarations is restricted to operations of type integer. Moreover, arithmetic operations on integer constants greater than 32 bits are not supported.
Policy DC
Ruleset RTL
Language VHDL
Type Block-level
Severity Error

Example

All constants must be computable during HDL compilation. If an arithmetic operation is performed while defining the value for constants, the value of the constant becomes non-computable during compile time.

Therefore, cast constants to type integer if you need to perform an arithmetic operation in a constant declaration. Otherwise, move the computation outside of constant declaration. For example, you can change the constant to a variable and perform the arithmetic operations on the variable. Note that computations on variables always produce logic. Following are examples of valid and invalid VHDL code that exhibit this problem and how to correct it.

DCVHDL_2270

Message: Aliases to existing aliases are not supported for synthesis.

Description The VHDL compiler supports aliases to signals, variables, and constants only. It does not support aliases that refer to existing aliases.
Policy DC
Ruleset RTL
Language VHDL
Type Block-level
Severity Error

Example

Following is an example of invalid VHDL code that exhibits this problem: 

-- Library includes
library IEEE;
